# สูตรคะแนนและข้อจำกัดของ TeamFit (tf-likert-v1 / tf-scoring-v1 / tf-role-rubric-v1)

## สถานะ
- **ยังไม่ผ่าน psychometric validation** — ทั้ง 8 แกนเป็น operational definitions สำหรับต้นแบบ ไม่ใช่ข้ออ้างว่าเป็น construct ที่แยกกันและผ่านการตรวจสอบทางสถิติ
- สูตร alignment เป็น **heuristic ของผลิตภัณฑ์** ก่อนใช้เป็นเครื่องมือคัดเลือกที่มีผลต่อการจ้างจริง ต้องตรวจ job relevance, reliability (เช่น internal consistency, test–retest), validity (construct/criterion), fairness (adverse impact, DIF) และเทียบกับหลักฐานทักษะและผลการทำงาน
- ไม่คัดลอกข้อสอบ คู่มือ หรือ scoring ของสำนักใด และไม่ใช่ Everything DiSC อย่างเป็นทางการ (ใช้แนวคิดพฤติกรรมที่ได้แรงบันดาลใจจาก DISC เท่านั้น)

## โมเดล 8 แกน (เรียงตามเข็มนาฬิกา)
D → Di → I → iS → S → SC → C → CD — คำนิยามอยู่ใน `src/lib/model/axes.ts`
- แกนผสม (Di, iS, SC, CD) **มีข้อคำถามวัดโดยตรง** 8 ข้อต่อแกน ไม่ได้สร้างจากค่าเฉลี่ยของสองแกน
- คะแนนสูงไม่ได้แปลว่าดีกว่า คะแนนต่ำไม่ได้แปลว่าขาดความสามารถ ไม่ตีความความฉลาด คุณธรรม หรือสุขภาพจิต
- MVP มีโปรไฟล์ผู้สมัครชุดเดียว: "พฤติกรรมในการทำงานที่ผู้สมัครรายงานด้วยตนเอง" (ไม่สร้าง Natural/Adapted จากคำตอบชุดเดียว)

## แบบประเมิน
- 64 ข้อ (8 ข้อ × 8 แกน) Likert 5 ระดับ: 1 แทบไม่ตรงกับฉัน · 2 ค่อนข้างไม่ตรง · 3 ตรงบางครั้ง · 4 ค่อนข้างตรง · 5 ตรงกับฉันมาก
- กรอบคำตอบเดียวกันทุกข้อ: พฤติกรรมในการทำงาน/โครงการช่วง ~6 เดือนที่ผ่านมา (ถ้ายังไม่เคยทำงาน ใช้บริบทการเรียน/กิจกรรมกลุ่ม)
- ทุกแกนมีข้อปกติและข้อกลับคะแนน; แต่ละแกนมี 1 คู่ข้อ (`pairGroup`) สำหรับดูความสอดคล้องบางส่วน **ไม่ใช่ข้อจับโกหก**
- ลำดับแสดงผลสลับแกน (D1, Di1, I1, …) ครั้งละ 8 ข้อ รวม 8 หน้า
- ข้อคำถาม, scale, reverse flag และ pair อยู่ฝั่ง server (`src/lib/assessment/items.ts`); ผู้สมัครได้รับเฉพาะ `id`, `position`, `text`

## คะแนนรายแกน ("คะแนนตามสเกลของต้นแบบ")
```
ข้อปกติ:        scored = r
ข้อกลับคะแนน:  scored = 6 − r
scaleScore_j  = 100 × (mean(scored ของแกน j) − 1) / 4      // 0–100, ไม่ใช่ percentile, ไม่ normed
```
- คำนวณเมื่อครบ 64 ข้อเท่านั้น ถ้าขาดจะรายงาน "ยังไม่สมบูรณ์" และไม่เติมคำตอบแทน
- ไม่บังคับให้ผลรวม 8 แกนเท่ากับ 100
- โค้ด: `computeScaleScores` ใน `src/lib/scoring/engine.ts`

## ดัชนีความสอดคล้องด้านพฤติกรรมกับบทบาท
สำหรับแกน j: คะแนนผู้สมัคร c_j, ช่วงเป้าหมาย [L_j, U_j], น้ำหนัก w_j ≥ 0, Σw_j > 0
```
distance_j   = max(L_j − c_j, 0, c_j − U_j)
alignment_j  = 100 − distance_j
overall      = Σ(w_j × alignment_j) / Σ(w_j)      // แสดงเป็นจำนวนเต็ม
```
- validate: 0 ≤ L_j ≤ U_j ≤ 100, 0 ≤ c_j ≤ 100, น้ำหนักเป็นศูนย์ทั้งหมดถูกปฏิเสธ
- ข้อความกำกับที่แสดงคู่ค่าเสมอ: "ค่านี้แสดงความใกล้กับช่วงพฤติกรรมที่องค์กรกำหนดตามสูตรของต้นแบบ ไม่ใช่เปอร์เซ็นต์โอกาสทำงานสำเร็จหรือคะแนนความสามารถ"
- ไม่มี threshold ผ่าน/ตก, ไม่มีป้าย Best Candidate / Hire / Reject, ค่าเริ่มต้นเรียงตามเวลาสมัคร
- เปิดดูได้ทุกจุด: สูตร, c_j, ช่วง, น้ำหนัก, distance, contribution (w_j·alignment_j/Σw) — ส่วน "ดูวิธีคำนวณดัชนี" ในรายงาน
- ช่วงเป้าหมายที่กว้างและน้ำหนักที่เปลี่ยนทำให้ผลรวมเปลี่ยนได้ ค่านี้จึงขึ้นกับ rubric ที่องค์กรกำหนด
- บันทึก `scoringVersion`, `assessmentVersionCode`, `roleProfileVersionId` คู่กับ `score_reports` ทุกครั้ง
- โค้ด: `computeAlignment`, `validateTargets`

## โปรไฟล์เป้าหมายของบทบาท (rubric เชิงทดลอง)
- AI (หรือ demo adapter) เสนอช่วง/น้ำหนัก/เหตุผล/หลักฐานจากบทสนทนา Role Discovery เป็น structured JSON ที่ผ่าน schema validation (`AiRoleProfileSchema` → `normalizeAiProfile` → `RoleProfileSchema`) ค่าถูก clamp ให้อยู่ใน 0–100 และน้ำหนัก 0–10
- ห้ามอนุมานจากชื่อตำแหน่ง; ความต้องการส่วนตัวของหัวหน้าบันทึกเป็น assumption แยกจากความต้องการของงาน
- องค์กรปรับและกด **ยืนยัน** → เวอร์ชันถูก freeze (`role_profile_versions.status = confirmed`) ลิงก์และ session ผูกกับเวอร์ชันนั้น การยืนยันเวอร์ชันใหม่ไม่กระทบผู้สมัครเดิม และ AI ไม่สามารถเปลี่ยนเป้าหมายเงียบ ๆ ได้
- เปรียบเทียบเฉพาะผู้สมัครที่ใช้ `assessmentVersion` และ `roleProfileVersion` เดียวกัน

## คุณภาพการตอบ (แยกจากดัชนี)
ทำครบหรือไม่, ระยะเวลา, ช่วงที่เลือกค่าเดิมติดกันยาวสุด, สัดส่วนค่าที่ใช้บ่อยสุด, ความต่างของคู่ข้อหลังกลับคะแนน (0–4)
เป็นข้อสังเกตเพื่อการพูดคุยเท่านั้น **ไม่สรุปว่าโกหก** และไม่แปลงเป็นเปอร์เซ็นต์ความเชื่อมั่นทางสถิติ

## บทบาทของ AI
1. ถามและสรุปความต้องการของตำแหน่ง (Role Discovery) 2. อธิบายผลที่คำนวณแล้ว (รายงานผู้สมัคร/องค์กร)
- AI ไม่มีสิทธิ์สร้างหรือแก้คะแนน ไม่มีเครื่องมือตัดสินรับ/ปฏิเสธ ไม่เห็นข้อมูลข้ามองค์กร และไม่ได้รับชื่อ/อีเมลผู้สมัคร (ได้รับรหัส เช่น C-7K3Q)
- เนื้อหาจากองค์กร/ผู้สมัครถูกห่อเป็น untrusted input (`<recruiter_message>`, `<context_data>`) และ system prompt สั่งให้เพิกเฉยคำสั่งในนั้น
- คำอธิบายทั้งหมดติดป้ายว่าสร้างโดย AI (หรือ Demo) และองค์กรควรทบทวน
