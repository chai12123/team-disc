# การทดสอบ

## รันอัตโนมัติ
```bash
npm test          # vitest: unit + integration (ต้องมี Postgres ทดสอบ ดู README)
npm run test:e2e  # Playwright ต่อ dev server ที่ seed แล้ว (PW_CHROMIUM_PATH=/path/to/chrome ถ้าไม่ดาวน์โหลด browser)
npm run lint && npm run typecheck
```

## สิ่งที่ทดสอบอัตโนมัติแล้ว

### Unit (`tests/unit/scoring.test.ts`)
- item bank: 64 ข้อ, 8 ต่อแกน, ทุกแกนมีข้อปกติ+ข้อกลับคะแนน, มีคู่ตรวจความสอดคล้อง, id/ลำดับไม่ซ้ำ
- ข้อกลับคะแนนใช้ 6 − r
- คะแนน 0 / 100 / 50 (คำตอบระดับกลาง) ทุกแกน
- ปฏิเสธคำตอบไม่ครบ (ไม่เติมแทน), ค่าเกินช่วง, ค่าไม่เป็นจำนวนเต็ม, ข้อที่ไม่รู้จัก
- สูตร alignment: อยู่ในช่วง = 100, ระยะห่างต่ำกว่า/สูงกว่า, การถ่วงน้ำหนัก, contribution รวมเท่า overallRaw, ปัดเป็นจำนวนเต็ม
- ช่วงกว้างขึ้น → ดัชนีสูงขึ้น, น้ำหนักมากขึ้นบนแกนที่ห่าง → ดัชนีต่ำลง
- น้ำหนักเป็นศูนย์ทั้งหมดถูกปฏิเสธ; ช่วง/คะแนนผิดขอบเขตถูกปฏิเสธ; แกนน้ำหนัก 0 ไม่มีผล
- response quality: ไม่ครบ, straight-lining, ความต่างคู่ข้อหลังกลับคะแนน, ระยะเวลา, ไม่มีคำว่า "โกหก"

### Integration กับ Postgres จริง (`tests/integration/flows.test.ts`)
- ลิงก์กลาง → หลาย session แยกกัน, token session ≠ token เชิญ; ลิงก์เฉพาะบุคคลใช้เริ่มได้ครั้งเดียว (409)
- ลิงก์หมดอายุ/เพิกถอน เริ่มไม่ได้ (410) และสถานะแสดงถูกต้อง; องค์กรอื่นเพิกถอนไม่ได้; token มั่ว → 404
- autosave + กลับมาทำต่อ (คำตอบ, หน้าปัจจุบัน), หน้าผู้สมัครไม่ได้รับ scoring key
- submit ไม่ครบ → 400; submit ซ้ำ → alreadySubmitted และมี score_report แถวเดียว; แก้คำตอบหลังส่งไม่ได้ (409)
- คะแนน/ดัชนีที่คาดไว้ตรงสูตร และบันทึก scoringVersion + roleProfileVersionId
- องค์กร A เข้าถึงข้อมูลองค์กร B ไม่ได้ (role, candidates, session, invitation → 404)
- ผู้สมัครเข้าถึงผลคนอื่นไม่ได้; invite token เปิด session/รายงานไม่ได้
- รายงาน AI: ผู้สมัครไม่เห็นช่วงเป้าหมาย/ดัชนี, องค์กรเห็น; การสร้างรายงานไม่แตะ score_reports
- prompt injection ในแชต: ไม่เปลี่ยน phase/คะแนน, โปรไฟล์ที่เสนอยังอยู่ในขอบเขต, normalize clamp ค่าผิด ๆ
- เปรียบเทียบ: คนละเวอร์ชันโปรไฟล์และคนที่ไม่ครบถูกแยกพร้อมเหตุผล, session เดิมยังผูกกับเวอร์ชันเดิม (freeze), < 2 คน → 400, ข้ามองค์กร → 404
- rate limit เกินแล้ว 429; CSV ป้องกัน formula injection (= + - @)

### Claude adapter กับ API จำลอง (`tests/integration/claudeAdapter.test.ts`)
- ไม่มี key/model → AIError(config)
- AI ส่ง JSON ผิด schema → AIError(schema); timeout → AIError(timeout); refusal → AIError(refusal); JSON ถูกต้อง → ผ่าน พร้อม provider/model

### E2E (`tests/e2e/flow.spec.ts`, Chromium + viewport มือถือสำหรับผู้สมัคร)
dev login → สร้างตำแหน่ง → คุยกับผู้ช่วย (demo) จนได้ร่าง → ปรับน้ำหนักและยืนยัน → สร้างลิงก์ (ไม่มีอีเมลใน URL) → เปิดลิงก์ใน context แยก (ไม่มี cookie องค์กร, เข้าหน้าองค์กรถูก redirect) → ยินยอม → ตอบ 8 ข้อ reload แล้วคำตอบยังอยู่ → ตอบครบ 64 ส่ง → รายงานผู้สมัคร (ไม่มีดัชนี) → submit ซ้ำผ่าน API ได้ alreadySubmitted → องค์กรดูรายงาน (ดัชนี + คำอธิบาย + คำถามสัมภาษณ์) → เปรียบเทียบ 3 คน ไม่มีป้าย Best/Hire/Reject

## ขั้นตอนทดสอบด้วยตนเองแบบสั้น
1. `npm run db:reset-demo && npm run dev` → เปิด http://localhost:3000/login กด `admin@demo.teamfit.local`
2. ตำแหน่งงาน → "+ สร้างตำแหน่ง" → ตั้งชื่อ → แชตกับผู้ช่วย ลองพิมพ์คำตอบขัดกัน (เร็วมาก + พลาดรุนแรง + ไม่ตามขั้นตอน) จะเห็นคำถามชี้ความขัดแย้ง
3. แท็บโปรไฟล์เป้าหมาย → ปรับช่วง/น้ำหนัก/เหตุผล → "ยืนยันโปรไฟล์และเปิดรับสมัคร"
4. แท็บลิงก์สมัคร → สร้างลิงก์กลาง → คัดลอก → เปิดใน **หน้าต่างไม่ระบุตัวตน** (จำลองมือถือจาก DevTools ได้)
5. อ่านหน้า consent → เริ่ม → ตอบบางข้อ → ปิดแท็บ → เปิดลิงก์ "กลับมาทำต่อ" คำตอบยังอยู่ → ตอบครบ → ส่ง → ดูรายงานผู้สมัคร → ลอง "ขอลบข้อมูลของฉัน"
6. กลับหน้าองค์กร → ผู้สมัคร → รายงาน: เปิด "ดูวิธีคำนวณดัชนี", ดูคุณภาพการตอบ, คำอธิบาย AI/Demo, เพิ่มบันทึก, พิมพ์ (Ctrl+P)
7. เลือกผู้สมัคร 2–4 คน → เปรียบเทียบ (small multiples / overlay ≤ 3 เส้น, ซ่อนชื่อ, เรียงตามดัชนีจะมีป้ายเตือน); ที่ Operations Coordinator จะเห็นกรณีคนละเวอร์ชันถูกแยก
8. ส่งออก CSV จากหน้าผู้สมัคร เปิดใน Excel/Sheets ตรวจว่าค่าที่ขึ้นต้นด้วย = ไม่ถูกตีความเป็นสูตร
9. ตั้งค่า → ดูคำขอลบ, ระยะเวลาเก็บข้อมูล, เพิ่มสมาชิก; ลองเข้าสู่ระบบด้วย `other-admin@demo.teamfit.local` จะไม่เห็นข้อมูลขององค์กรแรก
